# DocLock — Supabase Database Integration & Implementation Plan

> **Executive Summary**: This plan provides a complete, screen-first architectural blueprint for integrating Supabase into the **DocLock** medical examination preparation application. Every table, column, index, and RLS policy is strictly derived from real screens, user flows, and interactive state in the application.

---

## 1. Application Overview

- **Application Name**: DocLock — Medical Exam Preparation & Clinical Learning Platform
- **Target Audience**: Medical candidates preparing for high-stakes licensure exams (FMGE, NEET PG, USMLE Step 1, INI-CET).
- **Core Technology Stack**:
  - Frontend: React Native (Expo SDK 52, Expo Router v4, TypeScript, Reanimated, Safe Area Context)
  - Backend: Supabase (PostgreSQL 15+, Supabase Auth, Row Level Security, Realtime WebSockets, Supabase Storage)
  - State & Data Fetching: React Context / TanStack React Query + Supabase JS Client
- **Existing State**: The frontend UI is fully styled and interactive, utilizing modular mock datasets (`data/*.ts`). No persistent database or authentication backend is currently wired.
- **Architectural Philosophy**: **Screen → UI Requirement → Data Requirement → Table → Column → Relationship → RLS → Query**. No redundant tables or unneeded columns.

## 3. Screen-by-Screen Data Requirements

### Screen 1: Home Dashboard (`app/(tabs)/index`)
- **Information Required**:
  - Candidate profile: First name (`Alex`), avatar URL.
  - Active Target Exam: Exam name (`FMGE`), days remaining countdown (`84 days`).
  - Quick Resource Counters: Bookmarked items count (`142`), Flashcards count (`580`), Offline downloads count (`12`), Notes count (`34`).
  - Active Activity Carousel:
    - Ongoing live class: Session ID, title, subject, chapter, attendee count, faculty avatar/name, stream status.
    - Resume video: Class ID, title, subject, duration watched vs total, progress %.
    - Resume test: Test ID, title, MCQs solved vs total, time remaining.
    - Resume QBank: Topic ID, title, MCQs solved vs total, accuracy %.
  - Daily High-Yield MCQ: Question ID, topic, difficulty, clinical vignette, 4 options (A-D text), correct option ID, clinical explanation text.
  - Desktop Sync Status: Connected device count, last sync timestamp.
- **User Actions**:
  - Tap Quick Study Resource pill (navigate to `/bookmarks`, `/flashcards`, `/downloads`, etc.).
  - Tap carousel card (join live stream modal or resume video/test/qbank).
  - Select MCQ option (triggers enabled state for submission button).
  - Submit MCQ answer (validates choice, animates explanation card, stores user response).
  - Retest/Reset Daily MCQ.

### Screen 2: QBank Subject Directory (`app/(tabs)/qbank`)
- **Information Required**:
  - List of 19 medical subjects: ID, name, chapters count, total MCQ count, category tags (`pre-clinical`, `para-clinical`, `clinical`, `high-yield`, `short-subjects`), theme icon name, icon colors.
  - Category filter chip counts.
- **User Actions**:
  - Search subjects by text query.
  - Filter subjects by category chip.
  - Tap subject card to navigate to `/qbank/[id]`.

### Screen 3: QBank Subject Detail & Quiz Runner (`app/qbank/[id]`)
- **Information Required**:
  - Subject header: Subject name, total chapters, total MCQs, completed MCQs, overall accuracy %.
  - Chapters list: Chapter number, chapter title.
  - Subheading topics list: Topic ID, topic title, MCQ count, completed count, duration minutes, status (`unattempted`, `in-progress`, `completed`), flags (`isHighYield`, `isImageBased`).
  - MCQ Attempt Modal Data:
    - Topic questions array: Question ID, vignette, image URL, difficulty, options (A-D), correct option ID, peer percentage, comprehensive explanation, golden pearl, reference textbook citation.
    - User state: Selected option, isFlagged, isStruckThrough (A-D), time spent seconds.
- **User Actions**:
  - Filter topics by status or high-yield tags.
  - Search chapters and topics.
  - Expand/collapse chapter accordion.
  - Tap topic to open Mode Selection Modal (`Practice`, `Exam`, `Study`).
  - Execute MCQ Quiz: Select option, strike-through distractor, flag for review, toggle question palette, navigate next/prev, toggle timer, finish test.
  - Record session results to database.

### Screen 4: Video Directory (`app/(tabs)/videos`)
- **Information Required**:
  - Video subjects: Subject ID, name, chapters count, total duration hours, video lecture count, category tags, icon name & colors.
- **User Actions**:
  - Filter by category chip, search subjects, tap subject to navigate to `/videos/[id]`.

### Screen 5: Subject Classes & Playlist (`app/videos/[id]`)

  - Subject metadata: Total video count, total hours, completed count, progress %.

  - Search classes, filter by status or chapter, toggle bookmark, tap class to navigate to `/videos/class/[classId]`.

### Screen 6: Video Player & Lesson Detail (`app/videos/class/[classId]`)

## 5. Existing Database Analysis

### A. Existing Tables
- **Current State**: None in the mobile app project (`d:\Project Files\onlineCourse\app`).
- The application currently relies on in-memory TypeScript files (`data/homeData.ts`, `data/chaptersData.ts`, `data/mcqData.ts`, `data/recordedClassesData.ts`, `data/testsData.ts`, `data/liveClassesData.ts`, `data/quickResourcesData.ts`).

### B. Required Tables
- 22 core tables + 3 supporting junction/session tables are required to fully support the application without mock data.

### C. Existing Columns
- N/A (Fresh database setup for DocLock).

### D. Missing Columns
- All application data fields identified in Phase 4 must be created in PostgreSQL.

### E. Unused Columns
- The schema is strictly pruned to exclude unneeded enterprise or school-management tables (e.g. no student admission numbers, parents, tuition installments, or physical classroom numbers).

### F. Duplicate/Overlapping Elimination
- **Consolidation 1**: Bookmarks for MCQs, Videos, Pearls, and Flashcards are unified into a single polymorphic `user_bookmarks` table with a `resource_type` enum instead of 4 separate tables.
- **Consolidation 2**: Quiz attempts for topic drills and grand mock tests share a unified `quiz_attempts` and `quiz_attempt_answers` table with an `assessment_id` or `topic_id` nullable foreign key.
- **Consolidation 3**: Downloads for videos, slides, and audio share a single `user_downloads` table with media metadata.

## 6. Required Tables (Core Schema Architecture)

1. **`user_profiles`**: Registered candidate profile, avatar, candidate number (`#DL-XXXXX`), and Pro Pass subscription status.
2. **`user_settings`**: Target exam choice (`FMGE`, `NEET PG`), study reminders, and Wi-Fi preferences.
3. **`user_active_devices`**: Device synchronization list (e.g., MacBook Pro, iPad, Phone).
4. **`faculty_profiles`**: Medical doctors and educators leading lectures and live classes.
5. **`subjects`**: The 19 core medical subjects (Anatomy, Pharmacology, Pathology, etc.) with styling and categories.
6. **`chapters`**: Subject chapter modules.
7. **`topics`**: Granular clinical topics under chapters (e.g., *Brachial Plexus & Erb's Palsy*).
8. **`mcq_questions`**: High-yield clinical vignettes with golden pearls and textbook citations.
9. **`mcq_options`**: 4 options (A-D) per question with peer percentages and specific rationale.
10. **`quiz_attempts`**: Recorded test and drill sessions (mode, score, time, accuracy, national rank).
11. **`quiz_attempt_answers`**: User selected option, time spent, strike-through states, and flagged states per question.
12. **`assessments`**: Standardized tests (Grand Tests, Subject Tests, Mini Mocks, PYQs).
13. **`video_classes`**: Recorded video lectures with views count, rating, PDF slide URL, and linked MCQ topic.
14. **`video_timestamps`**: High-yield chapter time markers inside video lectures.
15. **`video_pearls`**: Bulleted clinical pearls extracted from video lectures.
16. **`user_video_progress`**: Playback seconds position, watch status, and percentage completed.
17. **`live_sessions`**: Live interactive lectures (scheduled, upcoming, live) with participant counts.
18. **`live_chat_messages`**: Real-time websocket chat feed during live streams.
19. **`live_polls`**: Interactive polls broadcast by faculty during streams.
20. **`live_poll_options`**: Options for live polls.
21. **`live_poll_votes`**: Real-time user votes on live poll options.
22. **`live_hand_raises`**: Direct audio question queue for candidates in live class.
23. **`flashcard_decks`**: Decks organized by medical subject.
24. **`flashcards`**: Flashcard question/answer pairs with high-yield golden pearls.
25. **`user_flashcard_reviews`**: Spaced repetition tracking (SuperMemo SM-2 parameters: repetitions, interval, ease factor).
26. **`user_daily_goals`**: Daily goal tasks checklist and progress for each candidate.
27. **`user_study_activity_logs`**: Historical daily study hours and completion metrics for weekly chart.
28. **`user_bookmarks`**: Unified study locker for saved MCQs, videos, clinical pearls, and flashcards.
29. **`user_downloads`**: Registry of downloaded media for offline verification and license checking.

## 8. Database Relationships / ERD Description

```
[auth.users] 1:1 [user_profiles] 1:1 [user_settings]
                       │
                       ├─ 1:N ── [user_active_devices]
                       ├─ 1:N ── [quiz_attempts] ── 1:N ── [quiz_attempt_answers]
                       ├─ 1:N ── [user_video_progress]
                       ├─ 1:N ── [user_flashcard_reviews]
                       ├─ 1:N ── [user_daily_goals]
                       ├─ 1:N ── [user_study_activity_logs]
                       ├─ 1:N ── [user_bookmarks]
                       ├─ 1:N ── [user_downloads]
                       ├─ 1:N ── [live_chat_messages]
                       └─ 1:N ── [live_poll_votes]

[subjects] ── 1:N ── [chapters] ── 1:N ── [topics] ── 1:N ── [mcq_questions] ── 1:N ── [mcq_options]
    │                                                               │
    ├─ 1:N ── [video_classes] ──────────────────────────────────────┘ (optional linked topic)
    │               ├─ 1:N ── [video_timestamps]
    │               └─ 1:N ── [video_pearls]
    │
    └─ 1:N ── [live_sessions] ── 1:N ── [live_polls] ── 1:N ── [live_poll_options]
                    ├─ 1:N ── [live_chat_messages]
                    └─ 1:N ── [live_hand_raises]

[faculty_profiles] ── 1:N ── [video_classes]
                   └─ 1:N ── [live_sessions]

[assessments] ── 1:N ── [mcq_questions]
              └─ 1:N ── [quiz_attempts]

[flashcard_decks] ── 1:N ── [flashcards] ── 1:N ── [user_flashcard_reviews]
```

### Relationship Types:
- **One-to-One (1:1)**:
  - `auth.users` ↔ `user_profiles` (enforced via primary key FK `user_profiles.id`).
  - `user_profiles` ↔ `user_settings` (`user_settings.user_id` as primary key).
- **One-to-Many (1:N)**:
  - `subjects` → `chapters` → `topics` → `mcq_questions` → `mcq_options`.
  - `faculty_profiles` → `video_classes` & `live_sessions`.
  - `video_classes` → `video_timestamps` & `video_pearls`.
  - `user_profiles` → `quiz_attempts` → `quiz_attempt_answers`.
  - `user_profiles` → `user_video_progress`, `user_bookmarks`, `user_downloads`, `user_daily_goals`.
  - `live_sessions` → `live_chat_messages`, `live_polls`, `live_hand_raises`.
  - `flashcard_decks` → `flashcards`.
- **Many-to-Many (N:M)**:
  - `user_profiles` ↔ `flashcards` mediated by `user_flashcard_reviews`.
  - `user_profiles` ↔ `live_poll_options` mediated by `live_poll_votes`.

## 10. Authentication & User Roles

### Supabase Auth Integration
- Handled via `supabase.auth.signUp()` and `supabase.auth.signInWithPassword()`.
- Automatic profile provisioning via PostgreSQL database trigger:
  ```sql
  create or replace function public.handle_new_user()
  returns trigger as $$
  begin
    insert into public.user_profiles (id, candidate_id, full_name, email, role, is_pro_pass_active)
    values (
      new.id,
      'DL-' || floor(10000 + random() * 90000)::text,
      coalesce(new.raw_user_meta_data->>'full_name', 'Doctor Candidate'),
      new.email,
      coalesce(new.raw_user_meta_data->>'role', 'candidate'),
      false
    );
    insert into public.user_settings (user_id, target_exam_name, target_exam_date)
    values (new.id, 'FMGE (Dec 2026)', '2026-12-15');
    return new;
  end;
  $$ language plpgsql security definer;
  ```

### Defined Roles & Permission Hierarchy
1. **`candidate`** (Default Student):
   - Read curriculum data (Subjects, Chapters, Topics, MCQs, Videos, Flashcards, Assessments).
   - Read/Write own study tracking (Quiz attempts, Video progress, Flashcard reviews, Daily goals, Bookmarks, Downloads, Devices).
   - Read/Write own Live class interactions (Post in live chat, vote in polls, raise hand).
2. **`faculty`** (Doctor / Educator):
   - All candidate read permissions.
   - Manage/Broadcast Live sessions, launch polls, moderate live chat.
   - Update faculty profile details.
3. **`admin`** (System / Academic Director):
   - Full CRUD across all tables (Publish curriculum MCQs, upload videos, configure assessments, manage candidate subscriptions).

## 13. Required Queries & Mutations

### 1. Home Dashboard (`app/(tabs)/index`)
- **Query**: Fetch user profile, active live class, daily MCQ, and latest unfinished quiz/video attempt:
  ```ts
  const { data: profile } = await supabase.from('user_profiles').select('*').eq('id', user.id).single();
  const { data: liveClass } = await supabase.from('live_sessions').select('*, faculty:faculty_profiles(*)').eq('status', 'live').limit(1).maybeSingle();
  const { data: dailyMcq } = await supabase.from('mcq_questions').select('*, options:mcq_options(*)').eq('is_high_yield', true).limit(1).single();
  const { data: lastVideo } = await supabase.from('user_video_progress').select('*, video:video_classes(*)').eq('user_id', user.id).eq('status', 'in-progress').order('updated_at', { ascending: false }).limit(1).maybeSingle();
  ```

### 2. QBank Catalog (`app/(tabs)/qbank`)
- **Query**: Fetch subjects with chapter and MCQ counts:
  ```ts
  const { data: subjects } = await supabase.from('subjects').select('*').order('name', { ascending: true });
  ```

### 3. Subject Detail & Quiz Launcher (`app/qbank/[id]`)
- **Query**: Fetch chapters, topics, and completion status for subject:
  ```ts
  const { data: chapters } = await supabase.from('chapters')
    .select('*, topics(*)')
    .eq('subject_id', subjectId)
    .order('chapter_number', { ascending: true });
  ```
- **Mutation**: Submit completed quiz attempt & answers:
  ```ts
  const { data: attempt } = await supabase.from('quiz_attempts').insert({
    user_id: user.id,
    topic_id: topicId,
    mode: attemptMode,
    total_questions: total,
    answered_count: answered,
    correct_count: correct,
    incorrect_count: incorrect,
    accuracy_percentage: accuracy,
    score: score,
    total_time_seconds: timeSpent,
    status: 'completed',
  }).select().single();

  await supabase.from('quiz_attempt_answers').insert(
    answerList.map(a => ({
      attempt_id: attempt.id,
      question_id: a.questionId,
      selected_option_label: a.selectedOption,
      is_correct: a.isCorrect,
      time_spent_seconds: a.timeSpent,
      is_flagged: a.isFlagged,
      struck_through_labels: a.struckThrough
    }))
  );
  ```

### 4. Video Lecture Player (`app/videos/class/[classId]`)
- **Query**: Fetch lecture details, timestamps, clinical pearls, and last progress:
  ```ts
  const { data: lecture } = await supabase.from('video_classes')
    .select('*, faculty:faculty_profiles(*), timestamps:video_timestamps(*), pearls:video_pearls(*)')
    .eq('id', classId)
    .single();
  ```
- **Mutation (Debounced)**: Update playback progress:
  ```ts
  await supabase.from('user_video_progress').upsert({
    user_id: user.id,
    video_id: classId,
    last_position_seconds: currentSeconds,
    progress_percent: Math.round((currentSeconds / durationSeconds) * 100),
    status: currentSeconds >= durationSeconds - 10 ? 'completed' : 'in-progress',
    updated_at: new Date().toISOString()
  }, { onConflict: 'user_id,video_id' });
  ```

### 5. Live Classroom Realtime Channel (`app/live/[id]`)
- **Subscription**: Realtime WebSocket channel for chat and poll updates:
  ```ts
  const channel = supabase.channel(`live-session-${sessionId}`)
    .on('postgres_changes', { event: 'INSERT', schema: 'public', table: 'live_chat_messages', filter: `session_id=eq.${sessionId}` }, payload => {
      setMessages(prev => [...prev, payload.new]);
    })
    .on('postgres_changes', { event: '*', schema: 'public', table: 'live_polls', filter: `session_id=eq.${sessionId}` }, payload => {
      refreshPoll();
    })
    .subscribe();
  ```

## 14. Data Flow Architecture

```
User Action (e.g. Tap Option & Submit Drill)
   │
   ▼
Screen Component (`app/qbank/[id].tsx` / `McqAttemptModal.tsx`)
   │
   ▼
Custom React Hook / Service (`hooks/useQbankSession.ts`)
   │
   ▼
Supabase Client Singleton (`lib/supabase.ts`)
   │
   ▼ (HTTPS POST / WebSocket)
Supabase API Gateway (PostgREST / GoTrue / Realtime)
   │
   ▼
PostgreSQL Engine + Row Level Security (RLS Enforcement: `auth.uid() = user_id`)
   │
   ▼
Target Tables (`quiz_attempts`, `quiz_attempt_answers`)
   │
   ▼
PostgreSQL Trigger (e.g. `update_user_activity_log()`)
   │
   ▼
JSON Response Payload
   │
   ▼
UI State Update (Score Dialog, Golden Pearls, Home Streak Gauge)
```

- **Validation**: Client-side schema validation via TypeScript interfaces before calling Supabase.
- **Error Handling**: Graceful fallback states with retry capability.
- **Offline Resilience**: Offline actions (bookmarks, video download registers) cached via AsyncStorage / local SQLite and synced when network resumes.

## 18. Potential Issues / Risks & Mitigations

1. **High-Frequency Video Progress Writes**:
   - *Risk*: Flooding database with updates every second during video playback.
   - *Mitigation*: Debounce updates to every 10–15 seconds and on video pause/exit.
2. **Chat WebSocket Concurrency in High-Attendance Live Streams**:
   - *Risk*: Rate-limiting or UI stutter with 1,000+ simultaneous chatters.
   - *Mitigation*: Supabase Realtime broadcast channels with client-side batching and rate limiting (max 1 message per 3 seconds per candidate).
3. **Offline Drill Completion Sync**:
   - *Risk*: User finishes a 50-question mock test in airplane mode and loses results.
   - *Mitigation*: Store completed attempt in SQLite / AsyncStorage queue; sync automatically when `NetInfo` reports connectivity.
4. **Large Test Submissions**:
   - *Risk*: Inserting 300 question answers individually.
   - *Mitigation*: Single batch `insert` query for all answers within a database transaction.

## 19. Future Scalability Considerations

- **Database Partitioning**: As the platform scales to hundreds of thousands of candidates, partition `quiz_attempt_answers` and `live_chat_messages` by month or user ID hash.
- **Read Caching**: Use TanStack Query with stale-while-revalidate caching to eliminate duplicate reads for static curriculum tables (`subjects`, `mcq_questions`, `video_classes`).
- **Storage CDN**: Place Cloudflare or CloudFront in front of Supabase Storage buckets for high-bandwidth video lecture caching and low-latency global streaming.
- **Automated Leaderboard / Rank Calculation**: Use scheduled Postgres functions (`pg_cron`) to recalculate national percentile ranks hourly rather than on-demand.
